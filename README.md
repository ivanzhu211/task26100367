# PulseLink 心跳历史健康核算库

断网设备会补传旧心跳，本库按**采样时刻**（而非报文接收时刻）核算历史在线率。
所有时间为已校准到同一时间轴的整数毫秒；调用方保证串行访问；数据全部驻留内存。

## API

```go
m := pulselink.NewMonitor()
m.Register(deviceID, activeAt)        // 建立监测起点，不隐含心跳
m.RecordHeartbeat(deviceID, sampledAt) // 可乱序、可重复（重复不改变结果）
s := m.Summarize(deviceID, endAt)      // s.Day / s.Week / s.Month
```

每个 `WindowSummary` 含 `Online`、`Degraded`、`Offline`（整数毫秒）与
`Uptime`（Online / 实际窗口长度）。窗口左端取 `max(监测起点, endAt-窗口长度)`，
左闭右开；恒有 `Online+Degraded+Offline == 实际窗口长度`。

健康状态只由采样时刻决定：时刻 t 取不晚于 t 的最后一条心跳 h，
`t-h < 90000` 为 Online，`90000 <= t-h < 300000` 为 Degraded，否则 Offline；
首条心跳之前一律 Offline。迟到的旧心跳会改写历史区间，再次查询即反映补传结果。

## 设计

每台设备的心跳存放在一棵按采样时刻有序的**笛卡尔树**（treap，键为采样时刻、
随机优先级满足堆序）中：

- 每个节点保存 `val`：从本节点心跳到其中序后继心跳这一段内三种状态的时长
  （仅由段长决定：Online 至多 90s，随后 Degraded 至多 210s，其余 Offline）。
  旋转不改变中序序列，因此一次插入只需更新新节点及其直接前驱两个 `val`。
- 每个节点维护子树 `val` 聚合和，支持 O(log n) 的前缀和查询。
- 查询窗口 `[L, R)` 转化为两次前缀和相减：`cum(R) - cum(L)`，
  再加上首条心跳之前的 Offline 段；窗口边界处的部分段按长度裁剪。
  不逐毫秒展开、不扫描窗口内心跳、不取整近似。

## 复杂度

设单设备已有不同心跳数为 n：

- `RecordHeartbeat`：摊还 O(log(n+1))。treap 期望 O(log n) 插入 +
  两次 O(log n) 点值更新（前驱与新节点），不重排序、不搬移历史。
- `Summarize`（每个窗口）：O(log(n+1))。两次前缀和 + 常数次二分。
- 空间：O(n)，每个不同心跳一个树节点（实测 100 万条约 69 MiB），
  随设备数与不同心跳数线性增长；不丢弃任何迟到心跳。

## 测试

```sh
go test ./...          # 全部测试（含压力测试）
go test -short ./...   # 跳过压力测试
go test -run TestStress -v .  # 只看压力测试耗时与内存
```

- `pulselink_test.go`：题目用例（0/400000 查 450000 → 140000/210000/100000，
  补传 200000 后 → 230000/220000/0）、恰达 90s/300s 阈值、监测不足完整窗口、
  左端之前/恰在右端/右端之后的心跳、重复与乱序不变性、窗口长度恒等式。
- `reference_test.go`：独立的慢速参考实现（保存全部心跳，查询时排序后按
  临界点逐段累加），对随机乱序与重复输入逐次核对三个窗口结果。
- `stress_test.go`：固定种子可复现。100 万条不同心跳（间隔 1ms..800s，
  约 62% 的空档超过 300s），分别以逆序与随机顺序到达，再做 1 万次不同终点
  查询并校验窗口长度恒等式；记录耗时与保留堆内存。参考数据（Apple Silicon）：
  逆序插入约 154ms（≈154 ns/条），随机插入约 1.5s，1 万次三窗口查询约 36–55ms，
  保留堆内存约 68.7 MiB。
